# Hex aerosol transport

`forecast --chemistry-config FILE` and `global --chemistry-config FILE` append any number of positive aerosol mass tracers to the active default WSM6/YSU atmosphere. The existing monotonic scalar transport carries them on the GPU. Aerosols have kg/kg dry-air units and do not enter water loading or latent heating. No default physics component is disabled.

A configuration uses schema `gpuwm-hex.chemistry/v1` and a nonempty `species` list. Each row requires `name`, `dry_deposition_m_s`, `settling_m_s` and `mass_extinction_m2_kg`. Names are unique lowercase identifiers. Velocities and optical coefficients are finite and nonnegative. These are explicit case assumptions, with no universal particle size or optical property hidden in the defaults. Smoke, dust bins and sea-salt bins use the same operator and metadata.

The conservative implicit finite-volume column operator mixes with the active PBL `exch_h`, applies a downward settling flux and deposits at the lower boundary. Each species gets separate committed dry-deposition, settling and emitted-mass ledgers. A failed step does not commit a ledger; restart payloads carry all ledgers and require the same configuration digest. Wet scavenging, aerosol feedback on radiation, humidity-dependent optical growth and chemical reactions are outside this transport implementation.

Input preparation belongs to the chemistry-emissions provider. Its `inputs` block supplies dated normalized initial and source frames through `chem_emissions.attach`. The forecast verifies the weather/source start time and mesh digest. Missing source coverage is refused. Regional chemistry is refused because the existing atmospheric LBC series does not yet force chemistry over its specified and relaxation zones. This prevents a run that silently leaves its plume boundary undriven. Other WOOF-route physics selections are refused rather than replaced by the default suite.

On the MPAS-A suite route (`--physics-suite`, for example `convection_permitting`) the same flag runs the same transport (`woof.hex.mpasphys.chemistry_v842`): the species rows follow the Registry scalars in the dycore's scalar block, so the same monotonic transport carries them; the MPAS physics never reads them. After each step the same column operator mixes them with MYNN's `kzh` (the suite's `exch_h`), settles, deposits and emits. Inputs, history fields, the `CHEMISTRY` attribute, `chemistry-receipt.json` and checkpoint ledgers are the ones described here. A moving region or a multi-card run on that route refuses chemistry by name: the move remap and the card partition carry the Registry scalars only.

History carries every mixing ratio and these per-species surface fields: `<name>_column_mass` in kg/m2, `<name>_surface_concentration` in micrograms/m3, `<name>_aod550`, `<name>_dry_deposition` and `<name>_settled_mass`. `aod550` sums the configured species. AOD is a dry bulk mass-extinction proxy. The history `CHEMISTRY` attribute records coefficients, basis and configuration digest. `chemistry-receipt.json` records global mass closure and surface maxima.

`engine-patches/chemistry-products.patch` extends the Rust converter for arbitrary species product names, validates surface rank/units/nonnegative finite values, and conservatively remaps mass fields. Build it in a private engine-source copy with `tools/build_chemistry_converter.sh ENGINE OUTPUT`. Set `WOOF_HEX_RW_MPAS_CONVERT` to the resulting `rw_mpas_convert` in the chosen Cargo target directory. Then the ordinary render door uses `woof.rustwx` and `rw_wrfbatch`, for example `--products var:wrf_smoke_column_mass,var:wrf_smoke_surface_concentration,var:wrf_aod550`. The converter retains the native species names without a per-species code path. The Rust store prefixes additional surface planes with `wrf_`; product requests include that store prefix. Normal products automatically include the configured species products.

The covering CPU tests are `tests/test_chem_transport.py`, `tests/test_species_row.py` and `tests/test_imported_init_carriers.py`. `tools/run_chemistry_kernel_gate.py OUTPUT` checks conservation, positivity, constant preservation and invalid geometry on a GPU at the global120 column count. That operator check is separate from real-case whole-forecast evidence.
